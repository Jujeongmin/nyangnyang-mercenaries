# 방치형 벤치마크 대비 개선안

비교 대상: **버섯커 키우기**(Legend of Mushroom) · 세븐나이츠 키우기 · AFK 저니 · 기적의 검.
전부 "화면을 안 봐도 자원이 쌓이고, 접속하면 5분 안에 쓸 곳이 끝난다"는 같은 루프를 쓴다.

이 문서는 **지금 저장소의 실제 수치를 읽고** 쓴 것이다. 인용한 값은 전부 `game/public/data/` 원본이다.

---

## 0. 지금 우리 구조 (실측)

| 축 | 현재 값 | 출처 |
|---|---|---|
| 스테이지 | 200단계, 벽 8개(St50~200), 벽 곱 48.5배 · 총 3200배 | `stages.json > curve.walls` |
| 1스테이지 소요 | 23초 (조우3 + 보스). 2배속 12초 · 3배속 8초 | `combat.json > stagePresentation.timing` |
| 반복 보상 | **골드 단독** (`requiredCp^1.35 × 3.62561e-7`) | `stages.json > rewards.repeatClear` |
| 방치 | 캡 9시간, 시간당 156.5클리어 × 효율 0.35 | `stages.json > idleReward` |
| 즉시 수령 | 2시간분 × (무료2 + 광고2) = 하루 8시간 | `dailies.json > idleReward.instantClaim` |
| 배속 | 1 / 2 / 3 — **전부 상시 무료** | `combat.json > clientRendering.speedUp` |
| 벽 탈출구 | 훈련소·던전·소환레벨·아레나·광고 5종 | `stages.json > curve.wallEscapeValves` |

## 1. P0 — 방치가 온라인보다 8.6배 손해다

**계산.** 방치는 `156.5 × 0.35 = 54.8` 클리어/시간으로 고정돼 있다 (`idleReward.hourlyFormula`).
그런데 온라인 파밍은 배속을 그대로 먹는다 — `main.js:2139` 가 클리어마다 골드를 준다:

- 1배속 온라인 = 156.5회/시간 → 방치의 **2.9배**
- 3배속 온라인 = 469.5회/시간 → 방치의 **8.6배**

`offlineEfficiency: 0.35` 의 근거 주석은 "1.0이면 켜둘 이유가 없다"인데, 배속을 계산에 안 넣어서
**의도한 격차(2.9배)의 3배**가 나 있다. 방치형인데 폰을 켜두고 보는 게 압도적으로 이득이다.
버섯커·AFK 계열은 오프라인 수익률이 온라인의 80~100% 다. 격차를 두더라도 이 정도는 아니다.

**제안 (택1).**

1. **방치 수익에 최고 배속을 반영한다.** `stagesPerHour` 를 `156.5 × maxUnlockedSpeed` 로.
   격차가 설계 의도인 2.9배로 돌아온다. 배속이 "방치 효율 업그레이드"가 되어 성장축으로도 산다.
2. `offlineEfficiency` 를 0.35 → 1.0 으로 올리고 캡을 9→6시간으로 줄인다.
   총량은 비슷하되 "안 켜도 손해가 아니다"가 성립. 대신 접속 빈도 유인이 캡으로 옮겨간다.

**추천은 1번.** 배속 시스템이 아래 3장과 한 덩어리로 묶인다.

닿는 파일: `stages.json > idleReward`, `main.js:731-735` (`idleGold`).
`validate.mjs` 에 **"방치 시간당 수익 ≤ 온라인 시간당 수익"** 불변식을 하나 추가할 자리다.

## 2. P0 — 소탕(Sweep)이 없다

지금 후반 파밍은 3배속으로도 8초/클리어다. St180 기준 골드 265,617/클리어라 액수는 충분하지만,
**유저가 화면 앞에 앉아 있어야 한다.** 벤치마크 전부 소탕을 넣는다:

| 게임 | 방식 |
|---|---|
| 버섯커 키우기 | 스테이지 도전은 수동, 파밍은 자동 반복 + 오프라인 정산 |
| 세븐나이츠 키우기 | 소탕권으로 N회 즉시 정산 |
| AFK 저니 | 신속 보상 — 하루 2회 무료 + 광고, 즉시 n시간분 |

우리에겐 `instantClaim`(2시간분 × 4회)이 그 자리를 일부 메우고 있다. **완전히 새로 만들 필요는 없다.**
빈 곳은 "지금 이 스테이지를 N번 즉시 돌린다"가 아니라 **"화면 안 봐도 최고 배속으로 돈다"**이다 — 1장 제안 1번이 그것을 덮는다.

**추가로 넣을 것은 하나.** `combat.json > clientRendering.skipBattle` 이 이미 "렌더를 멈추고 결과만 반영"으로
정의돼 있는데 UI 노출이 없다. **배속 버튼 옆에 4번째 상태로 "OFF(렌더 정지)"를 붙인다.**
발열·배터리 대응이라는 원래 이유가 그대로 살고, 소탕권이라는 새 재화를 안 만들어도 된다
(새 재화는 `economy.json` 예산 재계산을 부른다).

닿는 파일: `index.html > #speed`, `main.js:2261-2265`, `combat.json > skipBattle`.

## 3. P1 — 배속이 성장축이 아니다

지금 1/2/3배속이 처음부터 전부 열려 있다. 벤치마크는 배속을 **가장 체감이 큰 보상**으로 쓴다
(버섯커의 공격속도 증가, 기적의 검의 배속 해금). 우리는 그걸 공짜로 줘 버렸다.

**제안 — 배속을 퀘스트/패스로 나눠 잠근다.**

| 배속 | 해금 | 근거 |
|---|---|---|
| 1x | 기본 | |
| 2x | 퀘스트 Q12 근처 (튜토리얼 직후) | 해금 자체가 첫 "확 빨라졌다" 순간이 된다 |
| 3x | 퀘스트 Q40 (`stages.json > systemUnlocks` 라인에 맞춤) | 벽 St50 직전에 붙여 벽 체감을 완화 |
| **4x** | 신규. 패스 유료 트랙 or 장비 소환 Lv30 | 과금 훅. 1장 제안 1번과 묶이면 방치 수익 +33% |

**해금 기준은 CP 가 아니라 퀘스트다** — `quests.json > slotUnlockQuests.canonicalSource` 규칙과 같은 이유로,
뽑기 운이 배속 순서를 흔들면 안 된다.

4x 를 유료로 붙이면 **뽑기 재화 배출은 안 건드리므로 README 불변식 5(배출 상쇄)에 안 걸린다.**
다만 `economy.json > monetizationGap` 의 "무과금 3개월 = 과금 1개월" 계산은 다시 돌려야 한다 — 방치 수익이 곱해지는 항이라서.

닿는 파일: `combat.json > speedUp`(배열 → 해금 조건 객체), `quests.json`, `pass.json`, `economy.json`.

## 4. P1 — 버튼만 있고 없는 것 둘: 출석 · 이벤트

`main.js:2314-2323` 의 사이드 버튼 처리에서 `attend` 와 `event` 는 **`미구현` 토스트로 떨어진다.**
방치형에서 이 둘은 장식이 아니라 **접속 이유 그 자체**다.

- **출석** — 7일/28일 누적. 벤치마크 전부 있고, 우리는 `dailies.json` 에 일일 미션은 있는데 출석 트랙이 없다.
  이건 작은 작업이고 리텐션 대비 효율이 가장 높다.
- **이벤트** — 버섯커의 성장 이벤트(7일간 목표 달성 시 보상)가 표준. 우리 벽 구간(St160 이후 정체 33~92일,
  `curve.walls`)에 **기간 한정 목표**를 얹으면 정체가 "할 게 없는 기간"에서 "이벤트 기간"이 된다.
  새 재화 없이 **기존 재화의 지급 시점만 앞당기는** 형태로 설계하면 예산이 안 깨진다.

## 5. P2 — "다음 벽까지 무엇이 모자란지"를 안 보여준다

`curve.walls` 는 벽마다 `gates`(예: St120 = 장비 소환 Lv29 + 수정 동굴)를 이미 적어 두었다.
그런데 화면에는 스테이지 번호와 CP 만 나온다. 유저는 **왜 막혔는지**를 모른다.

버섯커·AFK 는 실패 시 "요구 전투력 X / 현재 Y" 와 함께 **부족분을 채울 버튼**을 바로 띄운다.

**제안.** 스테이지 실패(또는 `bossLocked`) 시 뜨는 패널에 세 줄을 넣는다:
`요구 CP` / `현재 CP` / `가장 싼 상승 수단 3개`(훈련소 · 장비강화 · 소환레벨 — `wallEscapeValves` 를 그대로 쓴다).
데이터는 전부 이미 있다. 새 시스템이 아니라 **있는 데이터를 화면에 꺼내는 일**이다.

## 6. UI 배치

지금 세로 한 화면에 얹힌 것 (`index.html` 실측):

```
상단   캡틴 아바타 + Lv + 닉 + CP + XP바 + 설정 + 재화 2종
전투   캔버스 + 스테이지/조우/타이머/배속 3버튼 + 보스이동
좌측   출석 · 우편 · 이벤트 · 훈련소 · 패스        (5개)
우측   아레나 · 도감 · 랭킹 · 보물창고             (4개)
코너   퀘스트 진행바
하단   스킬바 → 장비 12칸 + 제작대독 + 채팅 → 네비 5탭
```

**사이드 9개 + 하단 5탭 + 상단 위젯 6개 = 상시 20개.** 버섯커도 버튼이 많지만 **좌 3 / 우 4** 를 넘지 않고,
나머지는 하단 탭 안으로 접는다. 우리 쪽 문제는 개수보다 **분류 기준이 없다**는 것이다 —
출석(일일)·우편(수령)·이벤트(기간)·훈련소(성장)·패스(과금)가 한 줄에 섞여 있다.

**제안 — 축으로 가른다.**

| 자리 | 담는 것 | 기준 |
|---|---|---|
| 좌측 3 | 출석 · 이벤트 · 패스 | **기간이 있는 것.** 놓치면 사라진다 → 빨간 점이 의미를 갖는다 |
| 우측 3 | 아레나 · 랭킹 · 보물창고 | **경쟁·수령.** 남과 비교하거나 받아가는 것 |
| 하단 탭 안으로 | 훈련소 → 용병 탭, 도감 → 용병 탭, 우편 → 상단 프로필 | 상시 접근이 필요 없다 |

훈련소는 성장 시스템이라 용병 탭 안이 맞고, 도감도 마찬가지다. 우편은 버섯커·AFK 전부 상단 프로필 옆이다.
이렇게 하면 **사이드 9 → 6**, 상시 노출 20 → 17.

**배속 버튼**은 지금 전투 HUD 우측에 있는데, 3장에서 해금제로 바꾸면 **잠긴 배속이 보여야** 한다
(회색 + 자물쇠). 안 보이면 해금이 보상으로 안 읽힌다.

**빨간 점(hasnew)** 은 이미 우편·상점·패스·용병에 붙어 있다 (`main.js > renderTop`). 좌측을 "기간 있는 것"으로
모으면 점이 한 덩어리에 몰려 시선 경로가 하나로 정리된다.

## 7. 안 하는 게 낫다고 본 것

| 항목 | 이유 |
|---|---|
| 펫 / 탈것 | 성장축이 이미 6개(용병·스킬·장비·도감·소환레벨·훈련소)다. 7번째는 각각의 체감을 깎는다 |
| 실시간 PvP | 아레나(비동기)가 있다. 실시간은 서버 상시 연결이 필요하고 Verse8 연동 전엔 검증 불가 |
| 소탕권 신규 재화 | 2장 참조. `economy.json` 예산 재계산을 부르는데 얻는 게 skipBattle 노출과 겹친다 |
| 스테이지 200 → 300 확장 | St200 요구 CP 가 천장의 87%다 (`cpCeiling.note`). 늘리려면 천장부터 올려야 하고 그건 전 시스템 재계산이다 |

## 우선순위 정리

1. **방치 수익에 배속 반영** (1장) — 장르 정체성 문제. 수치 한 줄 + 불변식 하나
2. **배속 해금제 + 4x** (3장) — 1번과 한 덩어리. 과금 훅이 여기서 생긴다
3. **출석 구현** (4장) — 작업량 대비 리텐션 효율 최고
4. **UI 사이드 9 → 6 재배치** (6장) — 지금 네비 작업 중이라 같이 하면 싸다
5. **벽 안내 패널** (5장) — 있는 데이터를 꺼내는 일
6. **이벤트 시스템** (4장) — 가장 크다. 벽 구간 정체가 길어질 때 착수

# 8. UI 언어 개편 (2026-08-23 심야 분석)

사용자 판정: "지금 UI 가 전체적으로 마음에 안 든다." 벤치마크(버섯커·세나키·AFK)의
공통 UI 문법과 우리 상태를 대조했다.

| # | 장르 문법 | 우리 상태 | 조치 |
|---|---|---|---|
| 1 | 팝업 타이틀 = 중앙 문패 + 장식선 | 좌측 평문이었다 | **적용** — #ovt 중앙 골드 리본 |
| 2 | 네비 선택 탭이 자리에서 솟는다 + 발밑 발광 | 2px 이동뿐이었다 | **적용** — -7px 솟음 + 골드 빛받침 |
| 3 | 재화는 어두운 캡슐 pill + 아이콘 겹침 | 맨 텍스트였다 | **적용** — .cur 캡슐화 |
| 4 | 버튼 3위계 (주행동 골드 / 보조 / 비활성) | 9-slice 킷으로 이미 통일 | 유지 |
| 5 | 표면색 체계 | 하드코딩 51종 | **정규화** — --card/--ink/--ink2 토큰 58곳 치환 (시각 무변) |
| 6 | 숫자 = 두껍고 흰색+테두리, 라벨 = 작고 회색 | 대체로 준수 | 유지 |
| 7 | 상단 [+] 버튼 (재화 → 상점 바로가기) | 없음 | **후보** — 다이아 캡슐에 + 붙이면 상점 진입이 한 탭 |
| 8 | 팝업 등장 애니 (스케일 0.95→1 + 딤 페이드) | 즉시 표시 | **후보** — transform 한 줄, 부하 없음 |
| 9 | 메인 화면 좌우 아이콘에 남은 개수/타이머 배지 | 빨간 점만 | **후보** — 출석 D-n, 패스 남은 일수 |
| 10 | 전투 데미지 폰트 = 전용 두꺼운 숫자체 | 시스템 폰트 | **후보** — 폰트 에셋 필요 (font/ 에 있는지 확인) |

방향 잡을 때 주의: 4·5 처럼 **이미 서 있는 것**을 갈아엎는 것은 개편이 아니라 재작업이다.
남은 후보 7~10 은 전부 추가형이라 되돌리기 싸다.
