# 용병·스킬 바텀시트 + 보유함 도입

2026-08-21. 하단 네비의 **용병 / 스킬** 탭을 가운데 오버레이(`#ov`)에서 **바텀시트**로 바꾸고,
그 안에 전체 목록과 `자동강화` · `자동장착` 버튼을 넣는다. 버튼이 실제로 할 일이 있으려면
**보유함**이 필요하므로 뽑기 반영 흐름도 같이 바꾼다.

## 왜 지금 구조로는 안 되나

`applyPulls()` 는 뽑는 즉시 전부 처리한다 — 등급이 높으면 파티에 꽂고, 아니면 `cascade()` 로
레벨에 녹인다. 미장착 보유분이라는 개념 자체가 없다. 그래서

- 목록에 뿌릴 "보유했지만 안 낀 용병"이 존재하지 않는다
- `자동장착` 은 이미 끝나 있어 누를 게 없다
- `자동강화` 도 이미 끝나 있어 누를 게 없다

## 결정 (사용자 확인 완료)

| 항목 | 결정 |
|---|---|
| 목록 범위 | `characters.json` 전체 32종 · `skills.json` 전체. 미보유는 `???` + 회색 |
| 버튼 성격 | **즉시 실행.** 보유함을 도입하고 버튼을 눌러야 반영된다 (proto 방식) |
| 장착 영역 | 가로 아이콘 줄 (아이콘 + Lv). 세로 카드 아님 |
| 시트 높이 | 화면(`#app`)의 60% |
| 트랙 전환 | **하단 네비 탭이 직접 가른다.** 시트 안 토글은 없다 |
| 목록 정렬 | 등급 헤더 없이 **한 줄기.** 약한 것이 위, 아래로 갈수록 강함 |
| 액션바 순서 | `[자동장착]` 왼쪽 · `[자동강화]` 오른쪽 |
| 던전 | 같은 시트를 쓴다 (`mode-dg`). 던전 하나가 **한 줄** |

## 상태 추가

```js
// 미장착 보유분. 장착분은 지금처럼 S.party / S.skills 에 그대로 있다.
S.own  = { mercenary: [], skill: [] }   // {id, nameKo, grade, cls, level}
// 강화 대기열. 등급 문자열만 쌓는다 — dupeValue 가 등급에서 나오기 때문
S.pend = { mercenary: [], skill: [] }   // ['N','N','SSR', ...]
```

**장착분과 보유함은 배열을 나눠 가진다.** 같은 객체를 두 배열이 참조하게 하면
`JSON.stringify` → `Object.assign` 세이브에서 동일성이 깨져 레벨이 갈라진다.
`자동장착` 이 두 배열 사이에서 원소를 옮기는 방식이라 참조 공유가 필요 없다.

## 뽑기 반영 변경 (`applyPulls`)

도감 등록은 그대로. 그 아래를 바꾼다.

- **용병** — 같은 `id` 가 파티나 보유함에 이미 있으면 중복이다 → `S.pend.mercenary.push(grade)`.
  없으면 `S.own.mercenary.push({...level:0})`. **파티는 건드리지 않는다.**
- **스킬** — 같은 `id` 보유분이 있고 새로 나온 등급이 더 높으면 등급만 올리고
  **밀려난 옛 등급을 `pend` 로** 보낸다. 아니면 `pend.push(grade)`.
  없으면 보유함에 추가.

즉시 토스트로 알리던 이관 로그는 `자동강화` 시점으로 옮긴다.

## 버튼 동작

**자동강화(track)** — `S.pend[track]` 을 전부 `cascade(track, grade)` 에 흘려 보내고 비운다.
`cascade` 는 지금 것을 그대로 쓴다 (이월 카운터 · CP 내림차순 대상 선택 포함).
대상은 여전히 **장착분만**이다 (`cascadeTargets`). 보유함에 있는 것은 안 올린다 —
안 그러면 안 쓰는 데 레벨이 새고 CP 최적이 깨진다.

**자동장착(track)** — 장착분 + 보유함을 합쳐 CP 내림차순 정렬 후 앞에서 슬롯 수만큼 자른다.
나머지는 보유함으로 돌린다. **레벨은 그대로 따라간다** — 지금 `cascade(track, grade, level)` 로
환급하던 경로를 안 타므로 "편성에서 빠지면 손해" 문제가 애초에 안 생긴다.

- 용병 5칸
- 스킬 액티브 4칸 · 패시브 4칸 (`SK-A` / `SK-P` 로 가름)

`applyAutoEquip` 후 `scene.setParty` · `renderSkills` · `renderTop` 을 다시 부른다.

## 시트 구조

```
#sheetBg  (scrim, z 64, bottom:var(--navh))
#sheet    (z 65, bottom:var(--navh), height:60%)
  ├ 헤더    용병 <장착 5 · 보유 9> ......... [닫기]
  ├ 장착 줄  가로 아이콘 5칸 / 4+4칸 (등급 액자 + Lv)
  ├ 요약 줄  이월 N · 대기 +M / 다음 레벨까지 K  + 게이지
  ├ 목록     전체 32종 그리드. 보유 = 그림+이름, 미보유 = ??? 회색
  │          장착 중인 것은 금색 테두리
  └ 액션바   [자동강화 (N)]  [자동장착]     ← 고정, 스크롤 안 됨
```

**시트는 하단 네비 위에서 끝난다** (`bottom:var(--navh)`). 네비를 덮으면 용병↔스킬을
오갈 때마다 시트를 닫아야 한다. `--navh` 는 시트를 열 때 네비의 실측 높이로 채운다 —
`8%` 로 두면 네비의 9px 프레임 테두리 때문에 틈이 벌어진다.

목록 그리드는 도감의 `.cx-grid` / `.cx-cell` / `.cx-cell.lock` 을 그대로 재사용한다 —
`???` + 회색 처리가 이미 그 클래스에 있다. 새 CSS 를 만들면 두 화면이 갈라진다.

**등급으로 끊지 않는다.** 약한 것이 맨 위, 아래로 갈수록 강해지는 한 줄기다.
"내가 어디까지 왔나"가 스크롤 위치로 읽힌다. 스킬의 액티브/패시브도 줄로 안 가르고
칸 왼쪽 위에 `액`/`패` 한 글자로만 표시한다 — 자동장착이 둘을 각 4칸씩 따로 채우므로
구분 자체는 여전히 필요하다. 아직 못 뽑은 스킬은 등급이 없어(뽑을 때 굴린다) 맨 위로 간다.

보유 판정은 **도감 ∪ 보유함**이다. 도감만 보면 둘이 어긋났을 때 `???` 칸에 Lv 배지가
떠서 잠긴 걸 강화한 것처럼 읽힌다.

## 던전도 같은 시트

`#sheet.mode-dg` 는 장착 줄·요약 줄·액션바를 감추고 목록만 남긴다. 껍데기(높이 60%,
네비 위 정렬, 헤더, 닫기)를 그대로 쓴다.

**던전 하나가 한 줄이다.** 2열 카드로 두면 이름·층·열쇠·요구 CP 네 가지가 좁은 칸에
접혀서 어디를 돌지 고를 수가 없다. 한 줄이면 층·열쇠가 오른쪽 끝 고정폭(74px)에
세로로 정렬돼 6줄을 훑는 눈이 한 번만 움직인다.

잠긴 줄의 자물쇠는 `display:block` 이다 — 인라인으로 두면 그 줄만 라인박스가 커져
행 높이가 13px 틀어진다.

목록 HTML 과 클릭 배선은 `main.js` 가 준다 (`dungeonHtml` · `bindDungeons`).
열쇠 리필·요구 CP·`runDungeon` 이 전부 거기 있다.

`자동강화` 버튼은 `S.pend[track].length` 가 0이면 비활성. `자동장착` 은 지금 편성과
결과가 같으면 비활성 — 눌러도 아무 일 없는 버튼이 활성으로 보이면 고장으로 읽힌다.

## 스크롤바

OS 기본 스크롤바는 회색 각진 막대라 판타지 UI 킷과 안 맞는다. `index.html` 상단에서
**전역으로 감춘다** (`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`).
세로형 모바일 게임이라 손가락으로 미는 것이 전제고, 스크롤 자체는 그대로 된다.
새 스크롤 영역을 만들 때 개별 화면에서 다시 노출시키지 않는다.

`main.js` 가 2162줄이라 시트를 여기 더 넣으면 안 된다. 다른 화면들처럼
`app/src/view/` 로 뺀다.

## 세이브 호환

기존 세이브에는 `own`·`pend` 가 없다. `load()` 뒤에 없으면 빈 값으로 채운다.
버전은 `v:1` 그대로 둔다 — 필드가 늘기만 하고 기존 필드 의미가 안 바뀐다.
