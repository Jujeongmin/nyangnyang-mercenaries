# 냥냥 용병단 — 데이터 테이블

방치형 가챠 RPG (Verse8 / 웹 HTML5) 밸런싱 데이터.
**모든 수치는 서로 연동되어 있다. 하나를 바꾸면 연쇄 검증이 필요하다.**

## 핵심 공식

### 전투력 (CP)

```
CP_용병 = 등급계수 × (1 + 레벨 × 0.06)
CP_스킬 = 등급계수 × (1 + 레벨 × 0.06) × 스킬CP계수

CP_기본 = Σ CP_용병(5인) + Σ CP_스킬(8칸)

CP_총합 = CP_기본
        × (1 + 장비보너스)          // MAX 2.86
        × (1 + 도감보너스)          // MAX 1.32
        × (1 + 용병소환Lv × 0.005)  // MAX 1.25
        × (1 + 스킬소환Lv × 0.005)  // MAX 1.25
        × (1 + 장비소환Lv × 0.008)  // MAX 1.48
        × (1 + 훈련소보너스)        // MAX 1.40
```

**CP 천장 = 1,834,000** · St200 요구 = **1,600,000** (천장의 87%)

### 스탯 파생

```
statTotal = 등급계수 / class.cpDivisor
atk = statTotal × ratio.atk / 100   (def, hp 동일)

CP 검산: atk×2.0 + def×1.8 + hp×0.1 === 등급계수
```

**세 직군의 스탯은 완전히 동일하다.** ATK 30 / DEF 20 / HP 50, cpDivisor **1.010** 공통.
스테이지가 사실상 DPS 체크라 ATK 비율이 다르면 그게 그대로 직군 격차가 된다
(구 비율에서는 마법사가 전사보다 62% 강했다).

구분은 **환산 패시브**뿐이다. ATK 의 15% 에 해당하는 예산을 DEF/HP/공격속도에 다르게 배분한다.

| 직군 | 패시브 | atkFromDef | atkFromHp | atkSpeedAdd |
|---|---|---|---|---|
| 전사 | 수호의 힘 | 0.162 | 0.0144 | 0.018 |
| 궁수 | 속사 | 0.099 | 0.0396 | 0.018 |
| 마법사 | 마력 전환 | 0.036 | 0.0648 | 0.018 |

```
atkFinal = atkBase + def × atkFromDef + hp × atkFromHp
```

**환산은 스탯 증가 스킬을 전부 적용한 뒤에 한다.** 먼저 하면 방어 스킬이 딜로 안 바뀐다.
DEF+HP 노출 합은 세 직군 모두 0.88 로 같다 — 한 직군만 낮으면 방어 스킬을 낀 순간
그 직군이 뒤처진다 (궁수만 0.52 였을 때 실측 편차 5.93%).

참조 설계: 버섯커 키우기의 "체력을 올릴수록 강해지는 직업".

### 전투

```
mitigation = DEF_피격 / (DEF_피격 + 2.65 × stageRefAtk)
stageRefAtk = requiredCp × 0.04
damage = ATK × (1 - mitigation) × 패시브배율     (최소 1)
```

틱 100ms / 최대 60초 / 위치·사거리 없음 / 타겟 = 인덱스 최저 생존자 / 웨이브 클리어 시 **50% 회복**.

### 스테이지는 DPS 체크다 (`combat.json > stageRules`)

체력·방어력을 끄지는 **않는다.** 끄면 방어 스탯과 방어 스킬 7종이 통째로 장식이 되고
상관계수가 0.86 → 0.75 로 붕괴한다(실측). 대신 잡몹 피해에 배율을 걸어 사실상 죽지 않게 한다.

| 값 | 의미 |
|---|---|
| `mobDamageScale` 0.05 | 잡몹 피해 배율. 일반 웨이브에서 실질 무피해 |
| `bossDamageScale` 1.0 | 보스만 실제로 문다 |
| `mitigationApplies` true | DEF 감산 정상 작동 |
| `allyInvulnerable` false | 무적이 아니다. 수치로 안 죽을 뿐 |

실패 조건은 사실상 시간 초과 하나다. 전멸은 보스전에서만 현실적으로 일어난다.

**감산 기준은 공격자 ATK가 아니라 스테이지 기준값이다.** 공격자 기준이면 나보다 강한 적 앞에서 DEF가 자동 무력화된다(보스전 감산율 4% 붕괴).

### 스테이지 (벽 구조)

```
requiredCp(n) = requiredCp(n-1) × (1 + 기본성장) × (벽배수 or 1)
기본성장: St2-40 7.02% / 41-100 1.2% / 101-160 0.6% / 161-200 0.2%
```

| 벽 | 배수 | 게이트 | F2P 정체 |
|---|---|---|---|
| St50 | ×1.20 | 장비 소환 Lv13 | 8일 |
| St75 | ×1.30 | 장비 소환 Lv17 | 8일 |
| St100 | ×1.45 | 장비 소환 Lv21 + 훈련소 | 13일 |
| St120 | ×1.60 | 장비 소환 Lv29 (무한 해금) | 12일 |
| St140 | ×1.80 | 무한 6부위 + 강화 골드 | 18일 |
| St160 | ×2.00 | 용병/스킬 소환 Lv30 | **33일** |
| St180 | ×2.20 | 장비 Lv50+ / 훈련소 Lv150+ | **41일** |
| St200 | ×2.50 | 전 시스템 만렙 근접 | **92일** |

벽 사이는 거의 수평. 요구 증가가 전부 벽에 몰려 있다.

### 스테이지 보상 / 방치

```
골드 = requiredCp(n)^1.35 × 0.004068     (반복 클리어. 열쇠·제련석·다이아 없음)
초회 다이아 = 30 × (1 + floor(n/20))
방치 시간당 = stageGold(최고돌파) × 156.5 × 0.35   (최대 12시간)
일일 환산 = 696회 클리어
```

### 던전

```
일일 수령 = baseYield × 1.15^(층-1)
요구 CP   = unlockCp  × 1.18^(층-1)
```
수령(15%) < 요구 CP(18%) — 무한히 뚫리지 않는다.

### 퀘스트

```
k = ceil(N/6), slot = ((N-1) mod 6) + 1
supply = k≤1:1.0 / k≤2:0.9 / k≤3:0.8 / k≤4:0.7 / else 0.6
reward(N) = requiredResources(N+1) × supply(k)
```

### 캐스케이드

```
levelsTransferred = floor(soulValue[중복등급] / soulValue[대상등급])
remainder → 혼 적립
```

### 아레나

```
승률 p = 1 / (1 + (상대CP / 내CP)^6)
승자 잔여HP = clamp(0.08, 0.85, 1 - (상대CP/내CP)² × 0.9)
연출 길이 = 6 + 8 × (1 - 승자잔여HP)   → 6~14초
```
틱 시뮬 아님. HP바 드레인 연출을 결과에서 역산 생성한다.

## 절대 깨면 안 되는 불변식

### 1. 등급 서열
만렙 하위등급 CP < Lv0 상위등급 CP 가 전 구간 성립해야 한다.

| | N | R | SR | SSR | UR | LR |
|---|---|---|---|---|---|---|
| Lv0 | 100 | 250 | 600 | 1,500 | 4,000 | 14,000 |
| MAX | 160 | 475 | 1,320 | 3,750 | 11,200 | 47,600 |

> LR 등급계수는 반드시 **14,000**. 10,000이면 UR 만렙(11,200)에 역전당한다.

### 2. 직군 패시브는 자기 완결형
다른 시스템 수치를 참조하면 그리디 정렬이 최적해가 아니게 된다.
- ❌ `마법사 = 스킬 피해 +20%` → 시너지 부활
- ✅ `마법사 = 25% 추가타` → 자기 스탯만 참조

### 3. 시너지 없음
파티 시너지 / 속성 상성 / 직군 슬롯 강제 전부 삭제. 자동장착 `sort(byCP).slice(0,5)` 가 수학적 최적해가 되도록 보장하기 위함.

### 4. 확률 공시
`gacha.json` 이 단일 소스. 게임산업법(2024.3) 대상 — 트랙별 × 소환레벨 구간별 × **개별 아이템 단위**까지 공개 의무. 하드코딩 금지.

### 5. 총 뽑기 예산
무과금 D180 누적 **약 4,050회**. 여기서 소환Lv 34, 과금 3배속이 나온다.
무료 소환권 추가는 **재배치이지 증량이 아니다.** 늘리면 반드시 다른 배출을 줄여 상쇄한다.

| 추가 | 상쇄 |
|---|---|
| 무료 1000뽑 | 수정 동굴 다이아 250 → **190** |

### 6. 등급 체계는 두 벌
| 대상 | 등급 | 정의 |
|---|---|---|
| 용병·스킬 | 6단계 (N~LR) | `characters.json` / `skills.json` |
| 장비 | 10단계 (일반~무한) | `equipment.json > grades` |

확률표도 분리 — `rateBands`(용병·스킬) vs `equipmentRateBands`(장비).
장비 T10 보너스 **0.1848 고정**. 이 값이 CP 천장을 결정한다. (계열·세트 삭제로 세트분 0.35를 등급계수가 흡수 - 전 등급 x1.2322)

### 7. 슬롯 해금은 퀘스트가 단일 소스
`quests.json > slotUnlockQuests`. 용병 3칸 → Q8: 4 → Q20: 5.

### 8. 밸런스 4요소는 한 묶음이다
`cpWeights` · 감산 기준 · 스킬 효과 수치 · 직군 패시브가 서로 결합돼 있다.
**하나를 바꾸면 `sim/tune.js` 를 반드시 다시 돌려야 한다.** 실제로 스킬 효과를 고치자 직군 편차가 2% → 15%로 튀었다.

### 9. 전투 기여 0인 효과는 스킬에 넣지 않는다
CP가 0이 되어 CP 정렬 자동장착에서 영원히 꼴찌 → 미장착으로 남는다. 재화 보너스는 던전·유틸 아이템 등 CP 무관 계통에 붙인다.

### 10. 도감 예산 32% 고정
늘리면 CP 천장이 오르고 스테이지 곡선·벽·St200 목표가 전부 재계산 대상이 된다.

### 11. 계열·세트는 삭제됐다
장비는 `(부위, 등급, 강화)` 3속성뿐이다. 세트 보너스가 없으므로 자동장착은 **부위별 그리디**가 곧 최적해이고, 개별 교체가 총 CP를 낮추는 일도 없다.

### 12. 확정은 항상 유저가 누른다
용병·스킬·장비 세 트랙 모두 계산은 시스템이 하되 적용은 버튼이다. 자동 적용하면 방치형에서 돌아올 이유가 사라진다. 갱신 가능하면 탭에 빨간 뱃지를 띄운다.

## 시뮬레이터 검증 결과

| 항목 | 결과 | 목표 |
|---|---|---|
| 직군 편차 (순수 스탯) | **0.00%** ✅ | ±5% |
| 직군 편차 (스킬 8칸) | **0.70%** ✅ | ±5% |
| CP–실전 상관계수 | **0.8986** (사실상 도달) | 0.9 |
| 60초 타임아웃 | 0.0% ✅ | 발생 최소 |

구설계는 편차 2.09% / 상관 0.861 이었다. 스탯 통일 + 환산 패시브로 둘 다 개선됐다.
편차 0.00% 는 시뮬로 맞춘 값이 아니라 **구조로 보장된 값**이다 — 세 직군의 ATK 가 같다.

상관계수 0.8986 의 잔여 오차는 액티브 스킬 간섭이다(같은 틱 최대 2개, 쿨타임 경쟁,
딜 낭비). 스킬당 고정 CP 를 매기는 한 못 잡는다. 배분을 바꿔가며 재봤지만
0.8977~0.9010 사이에서만 움직인다.

### 상관계수 0.861을 수용한 이유
용병만 변화시키면 **0.981**이다. 스킬(특히 액티브)이 끌어내린다 — 액티브 4개가 서로 간섭한다(같은 틱 최대 2개, 쿨타임 경쟁, 딜 낭비, 힐·실드 중첩). **스킬 1개의 가치가 나머지 3개에 따라 달라지므로** CP를 스킬당 고정값으로 매기는 한 못 잡는다.

실용상 문제없다 — 자동장착이 가끔 2~3순위 조합을 고르는 정도의 오차이고, 유저가 수동으로 이기려면 스킬 간섭까지 계산해야 해서 현실적으로 불가능하다.

### 시뮬이 잡아낸 결함들 (기록)
1. **해석적 계산이 27% 틀렸다** — 집중 공격 때문에 딜은 제곱, 탱킹은 선형으로 작동한다
2. **감산 공식이 방어를 죽였다** — K를 공격자 ATK에 묶어 보스전 감산율 4% 붕괴 → 스테이지 기준값으로 교체
3. **스킬 효과가 등급 무관이었다** — UR이 N의 40배 CP인데 효과 동일
4. **웨이브 전량 회복** — 방어형 가치 소멸 → 50% 부분 회복
5. **아레나 틱 시뮬 불가** — 직군 편차 65~82%p. CP 확률 판정으로 전환

클라이언트는 **읽기만** 한다. 쓰기는 전부 서버 함수.

| 항목 | API |
|---|---|
| 가챠 판정 | [`remoteFunction`](https://docs.verse8.io/ko/docs/vxshop/gacha-example) |
| 유저 데이터 | [`$global.getMyState` / `updateMyState`](https://docs.verse8.io/ko/docs/gameserver/sdk/globalUserState) |
| 랭킹 | [`leaderboard`](https://docs.verse8.io/ko/docs/gameserver/sdk/leaderboard) |
| 아레나 스냅샷 | [`globalCollection`](https://docs.verse8.io/ko/docs/gameserver/sdk/globalCollection) |
| 광고 보상 | [서버 검증](https://docs.verse8.io/ko/docs/ads/server-verification) |

### ⚠️ 호출 제한 ~10회/초
- **자동강화** — 중복 수백 개를 단일 호출로 서버가 일괄 계산
- **자동 소환** — Lv60에서 배치당 700개. 1초에 1회 호출로 N개 결과 반환
- **스테이지** — CP 3구간 판정. 110% 이상 자동승리 = 서버 호출 0
- **CP 제출** — debounce 60초 + 최소 변화율 0.5% + 일 30회

### ⚠️ 타이머
장비 소환 레벨업 시작 시각과 완료 판정을 **서버가** 해야 한다. 로컬 시간이면 기기 시계 조작으로 즉시 완료가 되고 랭킹이 무너진다.

## 세이브 스키마 (`save-schema.json`)

최상위 21개 필드. **파생값(CP·스탯)은 저장하지 않는다** — 서버가 매번 재계산한다. 저장하면 조작 대상이 된다.

### 치명 필드 6개
| 필드 | 이유 |
|---|---|
| `upgradeSlots[].startedAt` | 서버 시각이 아니면 시계 조작으로 즉시 완료 치트 |
| `lastSeenAt` | 방치 보상 기준. 클라가 보내면 무한 방치 보상 |
| `entriesUsedToday` / `adUsage` | 일일 한도. 리셋 판정도 서버 시간 |
| `freePulls.claimedMilestones` | 중복 수령 차단 |
| `questPointsClaimed` | 중복 수령 차단 |
| `arena.lastSeasonClaimed` | 시즌 보상 lazy claim 중복 방지 |

**시각은 항상 "시작 시각"으로 저장한다.** 남은 시간을 저장하면 기기 시계 조작이 통한다.

일일·주간 리셋은 **lazy 처리** — Verse8에 스케줄러가 확인되지 않으므로, 접속·호출 시 `lastResetAt` 과 서버 시각을 비교해 필요할 때 초기화한다.
